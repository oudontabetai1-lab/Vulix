## 制約
- 変更は本タスクの範囲のみ。範囲外の問題は「報告のみ」で手を出さない。
- 検出/判定ロジックは純粋関数に分離し、ブラウザ非依存でテスト可能に保つ。
- 新機能・バグ修正にはテストを必ず追加。利用者向け仕様が変わるなら同じ PR で README/docs も更新。

## 完了手順（必須）
リポジトリ直下で以下を1回実行する:

```bash
scripts/orca/finish_task.sh --title "<簡潔なPRタイトル>" --commit "<コミットメッセージ>"
```

これで「push前テスト → commit → push → PR作成 → @codex review 投稿」まで自動化される。
以降のマージとセッションのクローズは `merge_watcher.sh` が自動で行うので、
このセッションでマージ操作はしない。Codex から指摘が返ったら修正し、再度 `finish_task.sh` を実行する。
