# Security Policy

## Reporting Security Vulnerabilities

The Vulix maintainers take security seriously. If you discover a vulnerability or potential security risk in Vulix, please report it responsibly so we can investigate and address it promptly.

### How to Report

Please **DO NOT** open a public issue, discussion, or pull request to report a security vulnerability. Public disclosure can put users and environments at risk.

Instead, please report security vulnerabilities privately via GitHub:

- Go to the **Security** tab of the repository.
- Navigate to **Advisories** under "Reporting".
- Click **Report a vulnerability** to open a draft private security advisory.

GitHub Private Vulnerability Reporting allows you to share vulnerability details, proof-of-concept exploits, and reproduction steps directly with the maintainers in a confidential channel.

### What to Include in Your Report

To help us review and resolve the issue quickly, please include:
- A description of the vulnerability and its potential impact.
- Step-by-step instructions or minimal reproducible proof-of-concept (PoC).
- Affected versions, platforms, or configuration flags.
- Any suggested remediations or mitigations, if known.

### Response Process

- maintainers will acknowledge receipt of the report and begin investigation.
- We will coordinate fixes and validation within the private security advisory.
- Once a fix is verified, a release and public advisory will be published acknowledging your responsible disclosure (unless you prefer to remain anonymous).
