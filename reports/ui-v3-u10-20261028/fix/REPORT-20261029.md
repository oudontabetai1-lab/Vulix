# U10 corrective fix — 2026-10-29

## Result

Fixed the Agent submission regression introduced between `140cd284` and `5a690926`. The exact browser regression test now passes with Chromium, focused UI event/capability tests pass, and the complete non-E2E suite exits 0.

## Root cause

On capability manifest HTTP 401, the client had no ready manifest `schema_version`; ingress rejected durable events as `backend_version_unavailable`. `EventStreamClient._markWireStale()` treated that compatibility result as a transport failure and immediately reconnected, closing the only WebSocket used by `submitAgentScan()`. The Agent function itself has no capability guard, but it could only send while `state.ws.readyState === OPEN`, so the reconnect loop made the Agent start request disappear.

The fix keeps rejection of events whose backend version is missing or incompatible and keeps the stale indicator, but does not reconnect for `backend_version_*` errors. Cursor gaps and other ingress failures retain their existing reconnect behavior. This leaves the open WebSocket available for Agent submission while Normal/Hybrid capability submission guards remain unchanged.

## Scope decision: `monitor.py`

No new `wscan/monitor.py` changes were made by this corrective commit. The existing U10 version emit is retained: the UI ingress reads the already served capability manifest's `schema_version`, and durable backend events need the corresponding `backend_version` value to perform that comparison. Removing the existing emit would leave the UI with no event-side version and make the Normal/Hybrid wire compatibility comparison impossible. The existing emit is additive and does not change the API shape of preexisting fields.
