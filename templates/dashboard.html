スキャン対象スコープ
検査するURLの範囲を限定します。空欄の場合は最初のターゲットURLと同じホストが対象です。
1行1URL、前方一致。ここに記載したURL配下のみ巡回・攻撃します。
ログインや外部認証など、巡回はするが攻撃ペイロードを送らないURLを指定します。
🚫
除外項目
巡回・攻撃の対象から除外するURLパスや、ペイロードを差し込まないフィールドを指定します。
1行1パターン。https://example.com/admin でフルURL前方一致、 /logout でパスのみ一致、/dontScan/* で配下を全て除外（ワイルドカード *）、 それ以外はパスへの部分一致（大小文字無視）。 巡回・フォームのaction URL の両方が対象。
カンマ区切り。CSRFトークンなど改ざんすると遷移が壊れるフィールドを除外します。

YAMLパスを指定。空欄＝デフォルトのペイロード辞書を使用。
攻撃シナリオ
「ログイン → 保護ページへ移動 → 検査」のような複数段階の操作を、視覚的なステップとして組み立てられます。
各シナリオは検査前に実行され、最後の 🌐 移動 先がそのシナリオの検査対象ページになります。
巡回後に画面を見ながら作る場合は「巡回レビュー」画面からも作成できます。

🧠 Agent Browser Mode (browser-use)
LLM が Playwright ブラウザを直接操作して自律的に脆弱性を探索します。
従来のクロール→攻撃パイプラインとは異なり、LLM 自身がページを観察し、ペイロードを選択し、結果を判断します。
必要: pip install browser-use と LLM API キー（ANTHROPIC_API_KEY / OPENAI_API_KEY）

🔀 ハイブリッドスキャン (Agent偵察 → 通常スキャン)
Phase 1: Agent Browser がサイトを探索し、ページ・フォーム・URLを発見します。
Phase 2: 発見した全URLをシードにして通常スキャンを実行します。
複雑な認証フロー・SPA・動的ページの発見と、網羅的なペイロードテストを組み合わせます。
必要: pip install browser-use と LLM API キー
Agent偵察設定

設定はブラウザセッション中に保持されます。エクスポート/インポートで他環境にも引き継げます。
